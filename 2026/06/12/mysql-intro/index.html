MySQL 数据库学习

发表于 2026-06-12 更新于 2026-09-30 分类于 数据库 阅读次数：

MySQL 是测试工程师进阶的分水岭技能。会不会写 SQL，直接决定了你在排查问题时是”等开发查日志”还是”自己上手定位”。

本专栏按 30 天计划整理，从零语法到实战应用。

为什么测试要学 MySQL

三个最实在的理由：

① 验证数据真的落库了

接口返回 code=0 之后呢？金币真的加了吗？订单真的写进去了吗？只信接口响应是自欺欺人——要去数据库里确认。

② 自己造测试数据

要测 100 级的角色、要测背包满的场景、要测 30 天没登录的账号——找开发帮你改数据，不如自己一条 SQL 改完。

③ 排查问题定位更快

线上反馈”道具没到账”，你能直接查：

没有记录 → 是没发下来；有记录但状态异常 → 是发放逻辑问题。这一条查询就能把问题甩给正确的方向。

专栏结构

本专栏按 30 天的学习内容重新整理为 9 章，重点是每一章都落到测试场景：

章节 内容 测试价值
第 1 章 CRUD 基础与查询入门 造数据 / 验证落库 / 定位问题
第 2 章 聚合、分组与多表关联 统计分布 / 找漏发数据 / 核对账目
第 3 章 索引与慢查询优化 用 EXPLAIN 写性能断言
第 4 章 事务、锁与并发问题 超卖 / 覆盖 / 重复领奖的根因
第 5 章 Python + MySQL 自动化 用例前置重置 / 批量造数 / 落库校验
第 6 章 库表设计与安全测试 数据库评审清单 / SQL 注入检测

另外还有散落在各章的关键结论——比如金额要用 DECIMAL 不能用 FLOAT、订单要存价格快照、utf8 存不了 emoji，这些都是测试时看一眼表结构就能发现的问题。

给测试的两个提醒

提醒一：只学 SELECT 是远远不够的

测试场景里经常需要 UPDATE 和 DELETE：

不会写 UPDATE，你测个每日重置功能就得等第二天。

提醒二：线上环境慎用 DML

安全习惯：

  1. 动手前先 SELECT 一遍，确认影响范围
  2. 加 LIMIT 限制影响行数
  3. 生产库操作前先备份，或者至少先 SELECT ... FOR UPDATE 试一下
  4. 能用测试环境就别碰生产

环境说明

本系列的实践基于一个游戏业务数据库（角色、背包、任务、订单等表结构），所有示例都是测试工作中真实会用到的查询。

适合人群：不会 SQL、或只会基础查询的测试工程师。
