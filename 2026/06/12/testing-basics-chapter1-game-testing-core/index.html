测试基础 第1章 - 游戏测试核心概念

发表于 2026-06-12 分类于 自动化测试 ， 测试基础知识 阅读次数：

1. 游戏测试 vs 软件测试

核心区别：软件测试验证”对不对”，游戏测试还要验证”好不好玩”。

维度 软件测试 游戏测试
目标 功能正确、无BUG 功能正确 + 体验流畅 + 趣味性
标准 客观（通过/不通过） 主观 + 客观，主观占比大
性能关注 响应时间、并发量 帧率、卡顿、发热、耗电
兼容性 浏览器/系统版本 不同机型 + GPU + 分辨率 + 操作方式
UI测试 布局正确、交互正常 还要看美术表现、动效节奏、操作手感

**恐龙岛实例 — 什么时候用”游戏测试思维”**：

  • 软件思维够用：商城购买道具 → 验证扣钻石正确、道具到账
  • 必须用游戏思维：领地争夺战斗 → 20人帧率、技能特效是否遮挡UI、击杀反馈是否”爽”、低端机玩30分钟后是否烫手
  • 混合场景：恐龙存储系统 → 数据读写是软件逻辑，但放生动画的快慢、误操作确认是游戏体验

2. 测试类型

类型 说明
功能测试 验证每个功能是否符合需求
兼容性测试 多机型、系统版本、分辨率下的一致性
性能测试 帧率、内存、CPU、发热、耗电
冒烟测试 新版本基础功能快速验证
回归测试 修复BUG后对相关区域再次测试
稳定性测试 长时间运行，观察闪退、内存泄漏
用户体验测试 操作手感、UI美观、新手引导

3. 测试用例设计方法

边界值 — 最常用！

测试输入范围的边界：最小值、最大值、刚好超出

等价类划分

将输入分为有效等价类和无效等价类，每类取一个代表值

场景法

模拟用户真实操作流程，设计端到端测试用例

恐龙岛示例 — 培养条数输入：

  • 正常值：10 → 成功
  • 边界值0：0 → 提示”必须大于0”
  • 边界值负数：-5 → 提示”必须大于0”
  • 非数字：abc → 无法输入或提示

4. 黑盒测试 vs 白盒测试

  • 黑盒测试：不关注内部代码，只看功能和表现（游戏测试以黑盒为主）
  • 白盒测试：关注代码实现和流程，检查语句/分支/路径覆盖

5. 游戏测试面试高频考点

  1. 游戏测试和软件测试的本质区别
  2. BUG 严重等级划分（致命/严重/一般/轻微/建议）
  3. BUG 报告标准模板（标题、版本、设备、步骤、实际结果、预期结果、截图）
  4. 自动化工具有哪些（Selenium/Airtest/Appium/pywinauto/Poco）
  5. 如何设计测试用例（边界值+等价类+场景法，覆盖正常/异常/边界/兼容）

一句话：软件测试保证”能用”，游戏测试还得保证”玩家愿意一直用”。
