Airtest - 移动端自动化测试

发表于 2026-06-12 更新于 2026-09-30 分类于 自动化测试 阅读次数：

Airtest 由网易开源，专为手机游戏和 App 的 UI 自动化设计。它的最大特点是基于图像识别——不依赖控件树，截个图就能点。

这个特性对游戏测试尤其友好：游戏 UI 多是自绘的，控件树里往往什么都拿不到。

为什么游戏测试用 Airtest

传统 UI 自动化靠控件定位（id / class / xpath）。但游戏引擎渲染的界面，控件树里常常只有一个大 Surface，具体按钮根本不在树里。

Airtest 换了个思路：把按钮截图存下来，运行时在屏幕上找这张图，找到了就点它。

代价是识别率受分辨率、画质、特效影响，但对游戏场景来说，这是目前最实用的方案。

核心能力

图像识别 API

API 作用
touch(Template(...)) 找到图片位置并点击
exists(Template(...)) 判断是否存在，返回坐标或 False
assert_exists(Template(...)) 断言存在，不存在则用例失败
wait(Template(...), timeout=10) 等待某个图出现
swipe() 滑动
text() 输入文本

专栏结构

  • 基础入门：安装、环境配置、连接真机/模拟器
  • 图像识别实战：截图精度、分辨率适配、识别失败排查
  • Poco 控件：控件树定位、常见 API
  • AirtestIDE 使用：录制回放、生成报告
  • 实战案例：游戏日常任务回归、挂机流程验证
  • 踩坑集锦：真机连接失败、多设备管理、脚本稳定性

三个现实提醒

① 图像识别不是万能的

同一张按钮图，在不同分辨率、不同画质档位、不同机型下长得都不一样。跨设备跑必然出问题。

应对：为关键按钮准备多套模板图，或者脚本里做分辨率判断。

② 自动化跑游戏很吃资源

一台设备跑一个游戏实例，跑 10 台就要 10 台设备。真机云（如网易云真机、腾讯 WeTest）是更现实的选择。

③ 先问”值不值得自动化”

游戏 UI 变动频繁，这个版本录的脚本下个版本可能全废。

适合自动化：登录流程、日常任务、领奖流程、回归测试的固定路径
不适合：体验评价、频繁改动的界面、只跑一次的验证

适合人群：游戏测试工程师、移动端 QA。
