测试基础 第2章 - BUG管理与测试用例实战

发表于 2026-06-12 分类于 自动化测试 ， 测试基础知识 阅读次数：

1. BUG 严重等级划分

等级 说明 恐龙岛举例
致命（Blocker） 游戏崩溃/核心流程阻断 点击”领地争夺”直接闪退
严重（Major） 核心功能不可用 商城购买扣了钻石但道具未到账
一般（Normal） 功能异常但不阻塞 后台挂机5分钟后停止攻击，UI仍显示”挂机中”
轻微（Minor） 不影响功能的瑕疵 NPC名字”迅猛龙”写成”讯猛龙”
建议（Suggestion） 体验优化 背包满提示只停0.5秒，看不清

核心理念：致命=不能玩，严重=核心玩不了，一般=能用但不对，轻微=能用但不爽，建议=能用但可以更好。

2. BUG 报告标准模板

3. 偶现BUG怎么处理？

  1. 详细记录环境、操作步骤、日志
  2. 尝试多种条件复现（切换设备、切换网络）
  3. 必要时协助开发加日志定位
  4. 在TAPD上标记”偶现”，附上所有已知信息

4. 测试用例设计实战 — 恐龙岛自动培养池

用 Excel 格式输出了完整的45条测试用例，覆盖6个模块：

模块 用例数 覆盖内容
权限控制 4条 VIP权限开关、权限变更
界面交互 13条 弹窗元素、恐龙选择、阶段选择、培养条数输入（正常/边界/异常）
自动培养逻辑 5条 自动进化、达到上限、培养计数、完成停止
资源管理 3条 卡片消耗、卡片不足（开启时/培养中）
关闭功能 3条 确认弹窗、是/否操作
异常处理 2条 网络中断、服务器重启

测试用例设计原则

  1. 正常流程覆盖：用户按预期操作应该成功
  2. 异常流程覆盖：网络断开、服务器重启、资源不足
  3. 边界条件覆盖：最小值0、最大值、负数、超大值
  4. 优先级标注：P0（核心必测） > P1（重要） > P2（一般）

Excel 用例模板字段

用例ID 模块 测试项 前置条件 操作步骤 预期结果 优先级 测试状态 备注

5. 测试流程

好的用例设计 = 边界值 + 等价类 + 场景法，覆盖正常/异常/边界/兼容。
