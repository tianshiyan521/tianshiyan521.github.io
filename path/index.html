学习路径

这个博客里的 40+ 篇文章，不是随手记的笔记，而是一条完整的测试工程师成长路径。
下面按「先学什么、后学什么」排好顺序，你可以从头往下走，也可以挑自己缺的那块补。

🗺️ 全景图

如果你是新手：从第 0 阶段开始，按顺序走。
如果你是转岗/跳槽：直接看第 1 阶段，接口测试是最好证明能力的方向。
如果你在带团队：第 0、1、5 阶段最值得让组员过一遍。

第 0 阶段 · 测试基本功

目标：能独立写出别人看得懂的用例，能提出让开发无话可说的 BUG 单。

文章 讲什么
测试基础 · 导读 这个系列值不值得看，先看这篇
第2课：BUG 管理与缺陷生命周期 优先级怎么定、偶现 BUG 怎么提
第4课：用例设计方法 等价类 / 边界值 / 因果图 / 错误推测 / 白盒覆盖

核心认知：用例设计方法不是考试题，是压缩测试工作量的工具。等价类帮你少测一半，边界值帮你找到 80% 的 BUG。

第 1 阶段 · 接口测试实战 ★

目标：能独立搭一套接口自动化工程，遇到没有文档的私有协议也能自己啃下来。

文章 讲什么
学习地图 整个系列的路线与前置知识
第1课：入门认知 HTTP 200 ≠ 用例通过、五大测试维度、幂等性
第2课：脚本骨架与断言设计 四块骨架、用例隔离、dig()/check() 断言设计
第3课：从客户端日志逆推私有协议 旗舰篇 —— protobuf 逆向、0x0A 陷阱、499 不是限流

为什么这阶段含金量最高：
大部分测试还停留在”点界面 + 报 BUG”。能读懂协议、能搭框架、能定位到具体字段问题的人，在整个团队里是稀缺的。第 3 课那个案例 —— 从日志逆推出一个没有文档的 protobuf 私有协议，并写出 36 条用例 —— 这种能力比会用一个工具值钱得多。

第 2 阶段 · 数据能力（MySQL）

目标：不依赖开发，自己查库定位数据问题。

文章 讲什么
MySQL 系列导读 9 章结构说明
第4章：CRUD 基础 金额为什么必须用 DECIMAL
第5章：联表与聚合 WHERE vs HAVING、用 LEFT JOIN + IS NULL 找漏数据
第6章：索引与性能 最左前缀、EXPLAIN、用 EXPLAIN 写性能断言
第7章：事务与锁 不可重复读 vs 幻读、无索引行锁升级表锁
第8章：Python 自动化 pymysql、参数化防注入、封装 GameDB 类
第9章：设计与安全 表关系、SQL 注入检测、数据库安全清单

核心认知：测试懂数据库，等于多了一双眼睛。很多”偶现 BUG”在界面上看不出来，一查库就清楚了。

第 3 阶段 · 性能测试（JMeter）

目标：能设计压测场景，能看懂报告，能定位瓶颈。

文章 讲什么
JMeter 导读 三个核心认知
基础与架构 GUI 写脚本 / CLI 跑压测、平均值会骗人
监听器 6 种监听器、错误率必须追查来源
断言 5 种断言、采样器成功 ≠ 业务成功
参数化 CSV Sharing Mode、__counter/__time/__threadNum
关联与提取 正则/JSON/边界提取器、Default Value 设 NOT_FOUND

核心认知：压测报告里最没用的数字是平均值。要看 90% Line —— 它才代表”大多数用户的真实体验”。

第 4 阶段 · 服务器排查（Linux）

目标：服务出问题时，你能自己上服务器看明白发生了什么。

文章 讲什么
Linux 导读 三条救命命令
第2章：性能监控 top / df / free 三件套
第3章：网络与定时任务 ping 通 ≠ 服务可用、CLOSE_WAIT 是代码 BUG
第4章：管道与日志分析 grep → awk → sort → uniq → sort -rn 组合拳

核心认知：load 要跟 CPU 核数比才有意义；%wa 高是磁盘瓶颈；free 显示内存小不一定是问题（要看 available）。

贯穿始终 · 面试与复盘

目标：把做过的事讲清楚，让人相信你。

文章 讲什么
面试题 · 总览 答题三层结构（框架 → 项目 → 局限）、高频必问六题
基础概念与 BUG 管理 基础题怎么答出深度
专项深挖 TCP/UDP、性能排查、数据不一致、排行榜

核心认知：面试答题的公式是 「通用框架 → 我怎么做的 → 这个方案的局限」。只说框架是背书，只说项目是流水账，加上局限才显得你真有判断力。

📌 一句话总结

这个博客想传递的不是”我会用哪些工具”，而是——
遇到一个从没见过的问题，我知道从哪下手。

工具会过时，排查思路不会。
